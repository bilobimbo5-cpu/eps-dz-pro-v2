# EPS DZ PRO

منصة رقمية متكاملة لأساتذة التربية البدنية والرياضية في الطور الابتدائي بالجزائر.

## المرحلة الحالية

هذه المرحلة تغطي:

- **قاعدة البيانات**: `eps_dz_pro_schema.sql` (يُستورد في Supabase SQL Editor)
- **المصادقة (Auth)**: تسجيل الدخول، إنشاء حساب، نسيت كلمة المرور، تعيين كلمة مرور جديدة
- **حماية الصفحات**: `middleware.ts` يمنع الوصول للصفحات المحمية بدون تسجيل دخول،
  ويوجّه الأستاذ تلقائيًا إلى `/onboarding` إن لم يكمّل الإعداد الأولي
- **Onboarding Wizard**: معالج من 8 خطوات (الاسم، الولاية، المديرية، المؤسسة،
  الطور، الموسم الدراسي، المستويات، وإنشاء أول قسم) يحفظ البيانات مباشرة في
  قاعدة البيانات عند الإنهاء
- **لوحة التحكم الكاملة**: `app/(app)/dashboard/page.tsx` — بطاقات إحصائية حقيقية
  (المؤسسات، الأقسام، التلاميذ، نسبة الحضور، الغيابات، الوثائق)، 4 رسوم بيانية
  تفاعلية (Recharts)، قسم "ماذا تريد أن تفعل؟" بأزرار سريعة، وقسم "آخر الأنشطة"
- **الهيكل العام (AppShell)**: `app/(app)/layout.tsx` يوفّر Sidebar قابل للطي
  (Desktop) / منزلق (Mobile) + Topbar (بحث، وضع ليلي، إشعارات، قائمة حساب) —
  أي صفحة تُضاف داخل `app/(app)/` ترث هذا الهيكل تلقائيًا
- **إدارة المؤسسات** (`/schools`): جدول + بحث + Modal إضافة/تعديل + حذف مع تأكيد
- **إدارة الأقسام** (`/classes`): جدول + بحث + فلترة حسب المؤسسة + Modal إضافة/تعديل
  (مرتبط بالمؤسسة والمستوى) + حذف مع تأكيد
- **إدارة التلاميذ** (`/students`): جدول + بحث + فلترة حسب القسم والحالة +
  تصدير CSV (متوافق مع Excel، يدعم العربية) + Modal إضافة/تعديل شامل (بيانات
  شخصية، حالة، إعفاء طبي) + حذف مع تأكيد
- **البطاقة الرقمية للتلميذ** (`/students/[id]`): معلومات شخصية، ملخص الحضور
  (نسبة الحضور/الغياب/التأخر محسوبة من `attendance_records`)، ملخص التقييمات
  (متوسط الأداء من `evaluation_results`)، الملاحظات — مع زر طباعة A4 يخفي
  تلقائيًا الشريط الجانبي والعلوي (`@media print` في `globals.css`)
- **مكوّنات UI مشتركة**: `Modal`, `ConfirmDialog`, `EmptyState`, `Spinner`,
  و`exportToCsv` (يمكن إعادة استخدامها في أي وحدة قادمة: الحضور، التقييمات...)
- **نظام الحضور والغياب** (`/attendance`): اختيار القسم + التاريخ + رقم الحصة،
  عرض تلقائي لتلاميذ القسم مع تمييز ذوي الإعفاء الطبي، زر "تحديد الجميع حاضر"
  ثم تعديل فردي بأربع حالات (حاضر/غائب/متأخر/معفى)، حفظ يُنشئ الجلسة تلقائيًا
  (`attendance_sessions`) ويحفظ سجلات كل تلميذ (`attendance_records`) عبر
  upsert — يدعم فتح جلسة موجودة مسبقًا وتعديلها دون تكرار. يعرض أيضًا ملخصًا
  إحصائيًا كاملًا للقسم (نسبة الحضور/الغياب/التأخر/الإعفاء) وسجل آخر 10 جلسات
- **الوحدات التعلمية** (`/units`): CRUD كامل (عنوان، موسم، فصل، مستوى، نشاط،
  كفاءة، هدف، عدد حصص مقترح) — تُستخدم كمرجع عند بناء الحصص
- **التخطيط** (`/planning`): تبويبات لأربعة أنواع (سنوي/فصلي/شهري/أسبوعي)،
  كل خطة مرتبطة بالموسم/المستوى/القسم مع محتوى حر قابل للتحرير
- **بناء الحصة — Session Builder** (`/lesson-builder`، قائمة عند `/lessons`):
  نموذج كامل بالمكونات السبعة المطلوبة (وضعية الانطلاق، الإحماء، الوضعيتان
  التعليميتان، الوضعية الإدماجية، التقويم، العودة إلى الهدوء) + بيانات أساسية
  (القسم، الوحدة، النشاط، المدة) + التنظيم ومعايير النجاح. يدعم حفظ كمسودة أو
  كحصة جاهزة، التعديل عبر `?id=`، وتكرار حصة موجودة (Duplicate) من قائمة الحصص
- **التقويم** (`/evaluations` وتفاصيل كل تقويم عند `/evaluations/[id]`):
  إنشاء تقويم (تشخيصي/تكويني/ختامي) مرتبط بقسم ونشاط وفصل، ثم بناء شبكة
  معايير ديناميكية (معيار + مؤشر + الدرجة القصوى)، وشبكة تسجيل نتائج تفاعلية
  (تلاميذ × معايير) تحسب تلقائيًا المجموع ونسبة الإتقان وتُصنّف كل تلميذ
  (ممتاز/جيد جدًا/جيد/متوسط/يحتاج إلى دعم) حسب سلّم بيداغوجي معتمد
  (`lib/evaluations/classification.ts`)، مع رسم بياني لتوزيع الأداء بين
  التلاميذ. هذه النتائج تغذّي تلقائيًا بطاقة التلميذ الرقمية ولوحة التحكم
- **مركز الوثائق** (`/documents`، التوليد عند `/documents/new`، العرض عند
  `/documents/[id]`): يعرض كل أنواع الوثائق الـ18 المزروعة في قاعدة البيانات
  (`document_types`) مجمّعة حسب الفئة (تخطيط، مذكرات، تقويم، حضور...). ست
  أنواع منها مُفعّلة بالتوليد التلقائي الكامل من البيانات الفعلية (`lib/
  documents/generators.ts`) بدون أي إعادة إدخال:
  - **قائمة التلاميذ** ← من جدول `students`
  - **كشف الحضور الشهري** ← محسوب من `attendance_sessions`/`attendance_records`
  - **مذكرة الحصة** ← من حصة محفوظة في Session Builder
  - **شبكات التقويم الثلاث** (تشخيصي/تكويني/ختامي) ← من نتائج وحدة التقويم

  بقية الأنواع (12 نوعًا: التخطيط السنوي، التقارير، بطاقات الأنشطة، العتاد...)
  تعمل حاليًا كوثائق عامة بعنوان ومحتوى حر قابل للتعبئة اليدوية والحفظ
  والطباعة — وهي المرحلة الأولى قبل ربطها ببيانات تلقائية مخصصة لاحقًا.
  كل وثيقة (تلقائية أو يدوية) تُحفظ في جدول `documents` كـ Dynamic Document
  (بيانات JSON + نوع + سياق) قابلة للمعاينة، الطباعة (A4، ترويسة موحّدة باسم
  الأستاذ والمؤسسة والتاريخ)، النسخ (Duplicate)، والتفضيل (Favorite)
- **لوحة تحكم الإدارة** (`/admin`، محمية بفحص `role === 'admin'` على السيرفر
  مع إعادة توجيه غير المخوّلين): إحصائيات على مستوى المنصة كاملة (المستخدمون،
  النشطون، المشتركون، الاشتراكات المنتهية، المؤسسات، الوثائق) محسوبة عبر
  RLS التي تسمح للإدارة برؤية كل الصفوف (`is_admin()` في الـ schema). أربعة
  تبويبات إدارية فعلية:
  - **المستخدمون**: عرض كل الأساتذة، تفعيل/تعطيل الحساب، ترقية/إلغاء صلاحية الإدارة
  - **المستويات**: إضافة/تعطيل/حذف مستويات دراسية (تتجاوز 1AP-5AP الافتراضية)
  - **أنواع الوثائق**: إضافة/تعطيل/حذف أنواع وثائق جديدة في `document_types`
    (يظهر النوع الجديد فورًا في مركز الوثائق لكل الأساتذة)
  - **المحتوى العام**: إدارة مكتبة الأنشطة المعتمدة (`activities.is_public`)
    التي تظهر لكل الأساتذة عند بناء الحصص والوحدات التعلمية

  **ملاحظة تشغيلية مهمة**: لا توجد حاليًا واجهة لترقية أول مستخدم admin (لتفادي
  ثغرة أمنية). لجعل أول حساب إداريًا، نفّذ في Supabase SQL Editor:
  `update public.users set role = 'admin' where email = 'بريدك@example.com';`
  بعدها يمكن لهذا الحساب ترقية حسابات أخرى من تبويب المستخدمين.
- **PWA والعمل دون اتصال**:
  - `public/manifest.json` + `public/icons/icon.svg`: التطبيق قابل للتثبيت
    (Add to Home Screen) على Android وiOS وDesktop
  - `public/sw.js`: Service Worker باستراتيجية Network-first للصفحات (مع
    نسخة مخزّنة كبديل) وCache-first للأصول الثابتة، مع `offline.html` كصفحة
    احتياطية للروابط غير المزارة سابقًا
  - `lib/offline/db.ts`: غلاف IndexedDB لتخزين لقطات بيانات (Cache) وقائمة
    عمليات معلّقة (Pending Writes Queue)
  - `components/pwa/PwaManager.tsx`: مُفعّل على مستوى التطبيق كاملًا — يسجّل
    الـ Service Worker، يراقب حالة الاتصال، ويعرض شريط حالة واضح (غير متصل /
    جارٍ المزامنة / عمليات معلّقة)
  - **تطبيق عملي كامل على وحدة الحضور** (الحالة المطلوبة صراحة في القسم 26):
    عند انقطاع الاتصال أثناء `/attendance`، تُعرض آخر نسخة محفوظة من قائمة
    تلاميذ القسم من IndexedDB، ويمكن تسجيل الحضور بشكل طبيعي؛ عملية الحفظ
    تُخزَّن محليًا في قائمة الانتظار بدل الفشل، وتتم مزامنتها تلقائيًا مع
    Supabase فور عودة الاتصال (`lib/offline/sync.ts`) دون أي تدخل من الأستاذ

  **حدود صريحة لهذه المرحلة**: دعم "العمل دون اتصال" مُطبَّق بالكامل على
  وحدة الحضور فقط كحالة استخدام مرجعية (الأكثر إلحاحًا ميدانيًا حسب القسم 28).
  توسيعه ليشمل وحدات أخرى (كتابة الملاحظات، إنشاء تلاميذ جدد أثناء انقطاع
  الاتصال...) يحتاج تكرار نفس النمط (`cacheSet`/`cacheGet` + `queueWrite`)
  لكل وحدة على حدة. كذلك، أيقونة PWA الحالية SVG بسيطة (لون + حرف) وليست
  هوية بصرية نهائية — يُنصح باستبدالها بأيقونات PNG احترافية (192×192 و
  512×512) قبل الإطلاق التجاري لضمان أفضل توافق مع كل المتصفحات.

- **الصفحة الرئيسية (Landing Page)** (`app/page.tsx`، القسم 30): صفحة تسويقية
  عامة عند الرابط الجذري `/` — Hero بعنوان وزر "ابدأ مجانًا"، 6 مميزات، "كيف
  تعمل" بأربع خطوات، إبراز المساعد الذكي، مقارنة الأسعار، أسئلة شائعة قابلة
  للطي، وCTA ختامي. المكوّنات منفصلة في `components/landing/` لسهولة تعديل
  النصوص أو الأسعار لاحقًا دون المساس ببقية الملف.

## التشغيل محليًا

1. أنشئ مشروعًا على [Supabase](https://supabase.com)
2. افتح **SQL Editor** ونفّذ محتوى `eps_dz_pro_schema.sql`
3. انسخ `.env.example` إلى `.env.local` وأدخل بيانات مشروعك:
   ```
   NEXT_PUBLIC_SUPABASE_URL=...
   NEXT_PUBLIC_SUPABASE_ANON_KEY=...
   ```
4. ثبّت الحزم وشغّل المشروع:
   ```bash
   npm install
   npm run dev
   ```
5. افتح `http://localhost:3000/signup` لإنشاء أول حساب أستاذ
6. (اختياري) لتفعيل المساعد الذكي (`/ai-assistant`)، أضف `ANTHROPIC_API_KEY`
   في `.env.local` — بدونه تظهر الصفحة برسالة خطأ واضحة بدل التعطّل الصامت

## القيود المعروفة (بصراحة كاملة)

### توليد PDF

الطباعة حاليًا تعتمد على `window.print()` مع تنسيق A4 مخصص (`@media print` في
`globals.css`) — أي أن "تصدير PDF" يتم عمليًا عبر خاصية "حفظ كـ PDF" في نافذة
طباعة المتصفح، وهي تجربة جيدة وتعمل على الهاتف والحاسوب، لكنها **ليست توليد
ملف PDF فعلي من السيرفر**. لتوليد ملفات PDF قابلة للتنزيل المباشر أو الإرسال
تلقائيًا (بدون تدخل المستخدم)، ستحتاج لاحقًا لدمج مكتبة مثل `@react-pdf/
renderer` أو خدمة تحويل HTML→PDF (مثل Puppeteer عبر Edge Function) — هذا
يستحق مرحلة مخصصة إذا كانت هذه الميزة أولوية.

كذلك، من أصل 18 نوع وثيقة مزروع في `document_types`، 6 أنواع فقط مربوطة
بتوليد تلقائي كامل من البيانات الفعلية (انظر القسم أعلاه). البقية وثائق عامة
يدوية حاليًا — ربطها بمصادر بيانات تلقائية (كالتخطيط السنوي بالوحدات، أو
تقارير نهاية الفصل بإحصائيات الحضور والتقييم) يحتاج عملًا إضافيًا لكل نوع
على حدة حسب الأولوية.

### CRUD التلاميذ والأقسام

- حقل `student_count` في جدول `classes` يُدخل يدويًا حاليًا عبر النموذج؛
  يُفضّل لاحقًا حسابه تلقائيًا (Postgres trigger أو COUNT عند القراءة) بدل
  الاعتماد على إدخال الأستاذ لتفادي عدم التطابق مع العدد الفعلي في `students`.
  ملاحظة: هذا العدد لا يتحدّث تلقائيًا بعد الاستيراد الجماعي من Excel/CSV أيضًا.

### أداء لوحة التحكم

بعض دوال `lib/dashboard/queries.ts` (خصوصًا `getEvaluationAverages`) تنفّذ عدة
استعلامات متتالية لكل تقييم. هذا مقبول في هذه المرحلة (بيانات قليلة)، لكن يُستحسن
لاحقًا استبدالها بـ Postgres View أو RPC واحدة تُجمّع النتائج في السيرفر لتقليل
عدد الرحلات إلى قاعدة البيانات عند نمو حجم البيانات.

### التزويد التلقائي بحساب الأستاذ (تم إصلاحه)

كانت النسخة الأولى تُنشئ صفوف `users` و`teacher_profiles` من طرف العميل
(المتصفح) مباشرة بعد `signUp` — وهذا تسبب في مشكلة حقيقية: بسبب غياب سياسة
RLS للإدراج على جدول `users` (تم إصلاحها)، كانت هذه الاستدعاءات تفشل بصمت،
فتبقى حسابات مسجَّلة في `auth.users` لكن بدون أي بيانات في `public.users`،
مما يكسر كل شيء لاحقًا (إضافة مؤسسات، أقسام...) بخطأ Foreign Key (409).

**الإصلاح الحالي**: تمت إضافة **Postgres trigger** (`on_auth_user_created`)
ينشئ صفوف `users` و`teacher_profiles` تلقائيًا داخل قاعدة البيانات نفسها
فور كل تسجيل جديد في `auth.users`، بصلاحيات `SECURITY DEFINER` تتجاوز RLS
بأمان. تمت إزالة الإدراج اليدوي من `app/signup/page.tsx` بالكامل. هذا أكثر
موثوقية جوهريًا لأنه لا يعتمد على نجاح أي استدعاء JavaScript إضافي من المتصفح.

**إن كنت تُحدّث مشروعًا قائمًا بالفعل** (وليس تثبيتًا جديدًا)، نفّذ ملفي
`auto_provision_trigger.sql` (لإضافة الآلية) و`fix_stuck_users.sql` (لإصلاح
أي حسابات سُجّلت قبل هذا الإصلاح ولا تملك بعد صف بيانات) في Supabase SQL
Editor — كلاهما آمن للتنفيذ المتكرر (idempotent).

### PWA والعمل دون اتصال

دعم "العمل دون اتصال" مُطبَّق بالكامل على وحدة الحضور فقط كحالة استخدام
مرجعية (الأكثر إلحاحًا ميدانيًا حسب القسم 28). توسيعه ليشمل وحدات أخرى
(كتابة الملاحظات، إنشاء تلاميذ جدد أثناء انقطاع الاتصال...) يحتاج تكرار نفس
النمط (`cacheSet`/`cacheGet` + `queueWrite`) لكل وحدة على حدة. كذلك، أيقونة
PWA الحالية SVG بسيطة (لون + حرف) وليست هوية بصرية نهائية — يُنصح باستبدالها
بأيقونات PNG احترافية (192×192 و512×512) قبل الإطلاق التجاري.

### ما تمت إضافته لاحقًا (بعد المراحل العشر الأساسية)

- **العتاد الرياضي** (`/equipment`): CRUD كامل (الاسم، النوع، العدد، الحالة:
  جيد/متوسط/تالف/بحاجة لإصلاح، مكان التخزين، تاريخ الاقتناء، المؤسسة)، بطاقات
  إحصائية (عدد الأصناف، إجمالي القطع، التالف، بحاجة لإصلاح)، فلترة حسب الحالة،
  وتصدير CSV
- **مركز الإشعارات** (`/notifications`): إشعارات **ذكية تُولَّد تلقائيًا**
  (`lib/notifications/generate.ts`) عند فتح الصفحة — تذكير بحصص اليوم الجاهزة،
  تنبيه إن لم يُسجَّل حضور قسم له حصة اليوم، وتنبيه قبل 7 أيام من انتهاء
  الاشتراك — مع منع التكرار (لا يُنشئ نفس الإشعار مرتين في نفس اليوم). دعم
  تحديد كمقروء (فرديًا أو الكل)، حذف، وفلترة (الكل/غير مقروء). جرس الإشعارات
  في الشريط العلوي يعرض العدد الفعلي غير المقروء ويقود مباشرة لهذه الصفحة
- **المساعد الذكي** (`/ai-assistant`): متصل فعليًا بواجهة Anthropic API عبر
  مسار خادم مخصص (`app/api/ai-assistant/route.ts`) يبقي المفتاح السري
  (`ANTHROPIC_API_KEY` في `.env.local`) بعيدًا عن المتصفح تمامًا. الأستاذ يكتب
  طلبًا بلغة طبيعية (مثال: "أنشئ لي حصة للسنة الرابعة حول الجري لمدة 45 دقيقة")
  فيُولَّد اقتراح كامل بالمكونات السبعة لبنية الحصة، **مع وسم واضح "محتوى
  مولّد آليًا"** كما اشترطت، وزر "فتح في Session Builder" يحفظه كمسودة
  (`generated_by_ai: true`) وينقل الأستاذ للتعديل والمراجعة قبل أي استعمال
  فعلي — تمامًا وفق قاعدة "لا يخترع بيانات تلاميذ حقيقية" التي حددتها
- **استيراد Excel/CSV للتلاميذ**: زر "استيراد" في `/students` يفتح نافذة
  ترفع ملف `.csv` أو `.xlsx`/`.xls` (`lib/utils/importParser.ts` عبر
  `papaparse` و`xlsx`)، تتعرّف تلقائيًا على أعمدة عربية أو إنجليزية شائعة
  (الاسم/اللقب/الجنس/تاريخ الميلاد/الرقم الداخلي)، تعرض معاينة لكل صف مع
  تحديد الصفوف غير الصالحة (اسم أو لقب مفقود) بالأحمر، ثم استيراد جماعي
  للصفوف الصالحة فقط إلى قسم واحد يختاره الأستاذ. يتضمن أيضًا زر "تنزيل
  نموذج CSV فارغ" لتسهيل التعبئة الصحيحة من البداية

**ملاحظة صريحة عن المساعد الذكي**: التوليد الحالي يُنتج بنية حصة تربوية
عامة فقط (وليس محتوى معتمدًا من وزارة التربية) — يجب على الأستاذ مراجعته
قبل الاستعمال، تمامًا كما هو موضّح في الواجهة. كما أن اسم النموذج
(`ANTHROPIC_MODEL`) في `.env.example` قد يحتاج تحديثًا حسب أحدث نموذج متاح
في حسابك على Anthropic وقت النشر.

### آخر دفعة: الوحدات المتبقية من خريطة الصفحات الأصلية

- **مكتبة الأنشطة الرياضية** (`/activities`): CRUD كامل لأنشطة الأستاذ الخاصة
  (الاسم، المجال، المستوى، المدة، الصعوبة، المهارات، الأدوات، ملاحظات
  تربوية) + تبويب "المحتوى المعتمد" لعرض الأنشطة العامة التي تضيفها الإدارة
  (قراءة فقط، التعديل محصور بلوحة الإدارة)
- **مكتبة التمارين** (`/exercises`): CRUD كامل (النشاط، المستوى، عدد
  التلاميذ، الزمن، التنظيم، التعليمات، معيار النجاح) + نظام مفضّلة (Star)
  وفلترة به + بحث
- **الإحصائيات المتقدمة** (`/analytics`، مستقلة عن بطاقات Dashboard):
  5 بطاقات إحصائية عامة، نسبة الحضور حسب كل قسم، متوسط الأداء حسب كل قسم،
  وتوزيع مستويات الأداء (ممتاز/جيد جدًا/جيد/متوسط/يحتاج دعم) عبر كل التقييمات
  المسجّلة — رسوم بيانية بتسميات دقيقة (`components/analytics/PercentBarChart.tsx`)
- **الاشتراك** (`/subscription`): عرض الخطة الحالية وتاريخ الانتهاء، ومقارنة
  الخطط الثلاث (مجاني/أساسي/احترافي) مع أزرار "قريبًا" للترقية — بنية جاهزة
  لربط وسيلة دفع جزائرية لاحقًا دون تغيير الهيكل، تمامًا كما طلبت في القسم 22
- **الإعدادات** (`/settings`): تعديل الملف الشخصي (الاسم، الهاتف، اللغة)،
  تغيير كلمة المرور، **وإغلاق/أرشفة الموسم الدراسي** (القسم L): زر واحد
  يؤرشف الموسم الحالي (`is_archived = true`) وينشئ موسمًا جديدًا نشطًا مع
  اقتراح تلقائي لتواريخه، مع قائمة بالمواسم المؤرشفة وتاريخ أرشفة كل واحد

**حدود صريحة لهذه الدفعة الأخيرة**:
- فتح أرشيف موسم قديم لتصفح بياناته بشكل منفصل (كما ورد في القسم L: "إمكانية
  فتح الأرشيف لاحقًا للرجوع إلى البيانات") غير مُفعّل بعد — الأرشفة تُسجَّل
  فعليًا في قاعدة البيانات، لكن كل صفحات المنصة (الأقسام، التلاميذ...) تعرض
  حاليًا بيانات كل المواسم مجتمعة دون فلترة حسب `school_year_id`. ربط كل
  صفحة بفلتر الموسم النشط يستحق مرحلة مخصصة.
- صفحة الاشتراك عرض فقط — لا يوجد ربط فعلي بوسيلة دفع (متعمّد حسب طلبك في
  القسم 22: "لا تربط الدفع بمزود واحد داخل النسخة الأولى").
- خيار الفرنسية في الإعدادات يظهر لكن الواجهة كلها بالعربية حاليًا؛ الترجمة
  الفعلية (i18n) لم تُبنَ.

## خلاصة نهائية

كل عناصر خريطة الصفحات الثلاثين تقريبًا من القسم 29 في الطلب الأصلي مبنية
الآن بواجهات فعلية متصلة بقاعدة بيانات حقيقية (لا نماذج شكلية ولا بيانات
وهمية). الفجوات المتبقية بين هذا وبين منتج قابل للإطلاق التجاري الفعلي هي
بالأساس: تدقيق أمني شامل (خصوصًا نقل منطق التسجيل من العميل إلى trigger)،
اختبار حمل حقيقي، توليد PDF من السيرفر بدل طباعة المتصفح، ربط وسيلة دفع،
وتصميم بصري نهائي (الأيقونات، الشعار) بدل العناصر النائبة الحالية.
